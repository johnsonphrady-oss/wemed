# Karpathy 極簡工程指引

本 skill 綜合 Andrej Karpathy 的實作哲學，結合本專案的 Steering 規則與 requirements.md 需求，作為每次實作的行為準則。

---

## 核心原則

### 1. 能不寫就不寫
- 每一行程式碼都是負債。只寫需求明確要求的功能。
- 不因「以後可能用到」而加入任何功能或設定。
- 不建立不必要的抽象層、helper、utility 或 wrapper。

### 2. 從最簡單方案開始
- 先用最直白的方式實作，確認能運作後才考慮重構。
- 優先選擇內嵌（inline）做法，而非過早模組化。
- 一個 HTML 檔 + 一個 CSS 檔 + 一個 JS 檔，能完成就不拆分。

### 3. 直接面對問題
- 不用框架、不用工具鏈、不用 build step。
- 遇到問題，先讀懂問題再動手，不猜測、不試錯堆疊。

### 4. 每項工作都要有可驗證標準
- 實作前先確認對應的驗收條件（來自 requirements.md）。
- 完成後逐一比對驗收條件，未達標不算完成。
- 驗證方式：在瀏覽器直接開啟 HTML 檔，目視確認每條條件。

### 5. 對本專案的具體限制
參照 `.kiro/steering/project-rules.md`：
- 純 HTML／CSS／JavaScript，無 Node / Vite / 框架 / 外部 API
- 所有程式碼放在 `docs/`
- 模擬資料硬寫於 JS 中
- 全繁體中文介面
- 響應式：桌機 ≥1024px、平板 768–1023px、手機 <768px

## 實作檢查清單（每次動手前確認）

- [ ] 這個功能在 requirements.md 中有明確要求嗎？
- [ ] 有沒有更簡單的寫法可以達到同樣效果？
- [ ] 有沒有引入任何框架、外部資源或不必要的抽象？
- [ ] 對應的驗收條件是哪幾條？實作後如何在瀏覽器驗證？

---

## 對應需求摘要（來自 requirements.md）

| 區塊 | 關鍵驗收條件 |
|------|-------------|
| 近期更新文件 | 顯示名稱、版次、日期；≤5 筆；可展開摘要 |
| 稽核缺失修改 | 顯示編號、描述、狀態色塊；≤5 筆；可展開負責人與日期 |
| 版本更新差異 | 顯示文件名、舊／新版次；≤5 筆；可展開差異說明 |
| 考題 | 顯示題目與文件名；≤5 筆；可展開選項與答案 |
| 整體 | 單頁、2×2 卡片（桌機）、單欄（手機）、全繁中、無外部請求 |
