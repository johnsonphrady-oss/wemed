# Requirements Document

## Introduction

本文件定義品質系統文件管理雛型畫面的需求規格。目標是以純 HTML／CSS／JavaScript 建立一個儀錶板，使用模擬資料呈現四大功能區塊：近期更新文件、稽核缺失修改、版本更新差異與考題。不包含後端、登入、資料庫或即時資料。

---

## Glossary

| 術語 | 說明 |
|------|------|
| 品質人員 | 使用本系統的主要使用者，負責文件管理與稽核追蹤 |
| 儀錶板 | 單一頁面，以卡片形式呈現各功能區塊 |
| 版次 | 文件的版本編號，如 v1.0、v2.1 |
| 稽核缺失 | 稽核過程中發現的問題項目，需追蹤至結案 |
| 模擬資料 | 硬寫於 JavaScript 中的假資料，無任何外部 API 請求 |

---

## Requirements

### 1. 近期更新文件

**使用者故事**
身為品質人員，我想在儀錶板上看到近期有異動的文件清單，以便快速掌握最新文件狀態。

**驗收條件**
- [x] 顯示文件名稱、版次與更新日期
- [x] 最多顯示 5 筆模擬資料
- [x] 依更新日期由新到舊排列
- [x] 每筆資料可點擊，展開顯示簡短變更摘要

---

### 2. 稽核缺失修改

**使用者故事**
身為品質人員，我想在儀錶板上看到尚未結案的稽核缺失清單，以便追蹤改善進度。

**驗收條件**
- [x] 顯示缺失編號、缺失描述與目前狀態（處理中／已結案）
- [x] 最多顯示 5 筆模擬資料
- [x] 狀態以不同色塊區分（處理中：橙色；已結案：綠色）
- [x] 每筆資料可點擊，展開顯示負責人與預計完成日期

---

### 3. 版本更新差異

**使用者故事**
身為品質人員，我想在儀錶板上比較文件前後版本的差異，以便了解修訂重點。

**驗收條件**
- [x] 顯示文件名稱、舊版次與新版次
- [x] 最多顯示 5 筆模擬資料
- [x] 每筆資料可點擊，展開顯示新舊版本的差異說明（純文字描述，非 diff 工具）

---

### 4. 考題

**使用者故事**
身為品質人員，我想在儀錶板上查看與文件相關的考題，以便確認人員對文件內容的理解程度。

**驗收條件**
- [x] 顯示考題題目與所屬文件名稱
- [x] 最多顯示 5 筆模擬資料
- [x] 每筆考題可點擊，展開顯示選項與正確答案

---

## 整體驗收條件

- [x] 儀錶板以單一頁面呈現，包含上方標題列與四個區塊卡片
- [x] 四個區塊卡片以 2×2 格線排列（桌機），單欄排列（手機）
- [x] 所有文字使用繁體中文
- [x] 所有資料為模擬資料，硬寫於 JavaScript 中，無任何外部請求
- [x] 頁面在桌機（≥1024px）、平板（768px–1023px）、手機（＜768px）均可正常瀏覽
- [x] 不包含登入、帳號管理、後端 API、資料庫或即時更新功能
